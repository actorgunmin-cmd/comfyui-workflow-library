# Comfy Cloud 사실

사용자 계정의 Comfy Cloud에서 확인한 내용이다. 괄호의 날짜가 측정일이다. Cloud는 계속 바뀌므로 결과를 좌우하는 항목은 작업 시점에 다시 확인한다.

## 1. 버전과 실행 전제

- 2026-11-09 기준 프런트엔드 1.59.8, ComfyUI v0.44.2, workflow_templates 0.7.64다. `/api/system_stats`는 로그인 없이 버전을 돌려줬고, `/api/object_info`는 로그인 없이는 401이었다.
- 사용자 노드팩은 설치할 수 없다. 코어 노드와 사전 설치 팩(KJNodes, WAS, layerstyle, ComfyUI-Image-Filters, VHS, Impact 등)만 쓸 수 있다(2026-11-08).
- 2026-11-09 점검에서 라이브러리가 쓰는 노드 201종은 Cloud에 모두 있었다. 모델 이름 99개 중 81개를 찾았고 18개는 현재 계정에 그 이름으로 없었다. 계정이 2026-11-08에 바뀌면서 가져온 모델이 따라오지 않았기 때문이다.
- Cloud 계정이 바뀌면 이전 계정의 가져온 모델, 입력, 출력이 보이지 않는다고 전제한다. 현재 계정 기준으로 필요한 모델 목록을 다시 확인한다(2026-11-08).
- 시험은 사용자가 로그인한 브라우저 세션 안에서 진행한다. 로그인이 끊겼으면 다시 로그인해 달라고만 요청한다. 키, 토큰, 쿠키를 추출하지 않는다.
- 공식 Cloud API v1(`X-API-Key`, 유료 티어)이 그래프 밖에서 일괄 처리하는 유일한 경로다(2026-10-22). 쓰려면 사용자가 직접 설정하게 하고 키 값을 채팅으로 받지 않는다.

## 2. 모델 이름과 가져오기

### 이름 규칙

- 가져온 모델은 Cloud 자산 이름으로 적어야 실행된다. 형식은 `Owner__Repo__file.safetensors`다. 원래 파일명은 실행 시 실패한다(2026-10-05 작업 기록, 원래 이름 0/2 성공, 접두어 이름 2/2 성공).
- Cloud 내장 모델은 원래 이름을 쓴다.
- `Repo` 부분에서는 점이 빠진다. 파일명의 점은 남는다. 예를 들어 저장소 `LTX-2.5-22b-IC-LoRA-Alpha-Gen`의 파일은 `Lightricks__LTX-25-22b-IC-LoRA-Alpha-Gen__ltx-2.5-22b-ic-lora-alpha-gen-0.9.safetensors`다(2026-10-05).
- 저장소 안 하위 경로는 이름에 들어가지 않고 파일명만 남는다(`Owner__Repo__file`, 2026-11-08). 파일명에 공백이 있던 사례는 `%20`이 이름에 그대로 남았다(2026-11-09 라이브러리 확인).
- 바이패스된 노드의 모델도 이름을 맞춘다. 사용자가 Ctrl+B로 켜는 순간 `value_not_in_list`로 막힌다(2026-11-09 점검).
- 이름을 바꿀 때는 안쪽 노드, 메인 컨트롤러 위젯, `widgets_values`, `widgets_values_named`, `properties.models`를 모두 맞춘다.

### 가져오기

- 문제 패널의 '가져오기'가 HF URL에서 누락 모델을 위 이름으로 가져온다(2026-11-07).
- 모델 가져오기는 Hugging Face와 Civitai 주소만 받는다(2026-09-26). 링크는 `resolve` 주소로 준다.
- API로는 `POST /api/assets/download`에 `{source_url, tags:["models",<type>], user_metadata:{source:"huggingface", source_url, model_type}}`를 보낸다. Scene embedding의 type은 `embeddings`다(2026-10-22).
- 대용량 저장소를 통째로 가져오지 않고 필요한 파일만 가져온다(2026-11-08).
- 게이트 Hugging Face 모델은 약관 동의, 토큰의 gated 읽기 권한, Cloud에 저장된 토큰이 모두 맞아야 성공한다(2026-10-21). 동의와 토큰 작업은 사용자가 직접 한다. "저장된 API 토큰이 유효하지 않거나 만료" 오류가 나면 Cloud 설정의 토큰을 사용자에게 갱신해 달라고 하고, 토큰 없이 받을 수 있는 공개 대체 링크를 같이 준다.
- 사용자가 직접 가져온 모델은 다른 계정에 없다. `/api/assets`의 `is_immutable:false`가 직접 가져온 항목이다(2026-10-22). 안내문의 모델표에 가져오기 대상으로 적는다.

## 3. 확인용 API

로그인된 Cloud 탭에서 `app.api.fetchApi`로 호출한다. 이 함수는 경로 앞에 `/api`를 붙인다.

| 용도 | 경로 | 비고 |
|---|---|---|
| 노드 존재 여부 | `/object_info` | 2026-11-09에 로그인 후 사용. 콤보 목록은 불완전하다 |
| 실제 모델 목록 | `/experiment/models`, `/experiment/models/{folder}` | Qwen 2.1 파일을 빠뜨린 사례가 있다 |
| 내 자산과 가져온 모델 | `/assets?include_tags=models`, `/assets?include_tags=loras` | 존재 판단은 이것을 우선한다 |
| 작업 상태와 결과 | `/jobs/{id}` | 출력의 `frame_count`, `fps`, `width`, `height`를 준다 |
| 실제 실행된 프롬프트 | `/history_v2/{prompt_id}` | 자주 폴링하면 429가 난다. 폴링은 `/jobs/{id}`로 한다 |
| 버전 | `/system_stats` | 로그인 없이 가능(2026-11-09) |
| 이미지 업로드 | `/upload/image` | 내용 해시 이름으로 저장된다 |
| 저장 워크플로 | `/userdata` | 경로가 NFD일 수 있다. 목록이 준 경로를 그대로 쓴다 |

## 4. 워크플로 불러오기와 입력 파일

- `app.loadGraphData(wf, true, true, 'name.json')`는 새 탭으로 연다. 탭에서 만든 JSON을 넣을 때 쓴다(2026-11-07).
- 큰 JSON은 gzip + base64로 탭에 전달한다. 긴 base64를 손으로 다시 입력하지 않는다. 글자 하나만 틀려도 gzip 해제가 실패한다. 이미 불러온 그래프를 JS로 고치는 쪽이 낫다(2026-11-07).
- 전송용으로 JSON을 줄일 때 노드 `mode`를 지우면 바이패스 노드가 켜져 `division by zero`, `tuple index out of range`가 난다(2026-11-08).
- 임시 저장은 `app.extensionManager.workflow.saveWorkflow(activeWorkflow)`다. 대화상자 없이 `workflows/<name>.json`을 만든다(2026-10-22).
- 입력 파일은 내용 해시 이름으로 저장된다. `/upload/image`는 `<sha256>.png`를 돌려주고 subfolder는 무시한다. 원래 이름은 `/api/assets`의 `display_name`, `file_path`에만 있다(2026-10-22). 업로드 때 메타데이터가 빠질 수 있으니, 로컬 파일의 SHA256이 달라도 디코딩한 픽셀로 동일성을 판단한다(2026-11-08).
- 로컬 파일을 Cloud 탭으로 보낼 때는 파일 선택기를 쓴다. Cloud 페이지의 CSP가 localhost 접속을 막기 때문이다(2026-10-22). 업로드 폴더를 준비해 사용자가 한 번만 고르게 한다. CSP를 우회하는 방법은 쓰지 않는다.
- 공개 CORS 호스트의 시험 이미지는 Cloud 페이지 안에서 받아 `/upload/image`로 올릴 수 있다(2026-11-07).
- 파일 전송이 막히면 전체 시험을 고집하지 않고 지금 Cloud에서 가능한 것만 시험한다. 빠진 대상을 보고한다(2026-11-08).
- `LoadVideo`와 `LoadImage`는 `하위폴더/파일.mp4 [output]` 형식으로 이전 출력을 입력으로 쓸 수 있다(2026-11-08).
- 방금 올린 이미지는 열린 탭의 `LoadImage` 목록에 없어 빨간 표시가 뜰 수 있다. 실행은 되고, 페이지를 새로 고치면 사라진다(2026-10-22).
- 저장 후 다시 불러오면 `LoadVideo`에 빈 `video-preview` 키가 생긴다. 해롭지 않으니 API 비교 전에 정규화한다(2026-11-08).

## 5. 실행과 결과 받기

- 동시 실행은 1건이다. 작업 시간이 그대로 합산되고 무거운 작업이 전체를 막는다(2026-10-22, 2026-11-07). 가벼운 파일부터 돌린다.
- 유료 파트너 노드는 `/prompt` 직접 제출 시 Unauthorized가 난다. 앱의 큐 실행 경로를 쓰고 인증 토큰을 추출하지 않는다. 사용자 승인 없이 돌리지 않는다(2026-11-07~08).
- 유료 노드를 randomize로 두면 다시 큐에 넣을 때마다 다시 과금된다(2026-11-09 점검).
- 브라우저에서 JS를 실행하는 도구는 호출 1회를 40초 안에 끝낸다. 이 환경의 도구 제한이 45초였다(2026-11-07).
- 서명된 다운로드 URL은 응답 파라미터를 지우면 SignatureDoesNotMatch가 난다. 전체 URL을 그대로 쓴다(2026-10 작업 기록).
- 출력 파일을 받을 때 `LoadVideo` 미리보기가 잡힐 수 있으니 저장 노드의 출력을 지정한다(2026-10 작업 기록).
- 출력 파일에는 워크플로 메타데이터가 들어가므로, 동일 여부는 파일 해시가 아니라 프레임으로 비교한다(2026-10 작업 기록). MP4에 들어 있는 API prompt로 실제 실행값을 확인할 수 있다(2026-09-27).
- Cloud 입력 원본이 해시 이름으로 받아질 수 있다. 다운로드 파일이 해시 이름이면 입력 원본일 수 있으니 SHA256으로 확인한다(2026-10 작업 기록).
- 캔버스 `toBlob` 캡처에는 프롬프트 칸 같은 DOM 위젯이 빠진다. UI 증거는 실제 스크린샷으로 남긴다. 캔버스를 크게 리사이즈하면 2D 컨텍스트가 깨질 수 있어 새 탭을 연다(2026-11-08).
- Chromium `video` 태그는 ProRes를 디코딩하지 못한다. 미리보기는 H.264로 다시 인코딩한다(2026-11-09).
- Qwen-Image 2.1 Turbo(int8, 8스텝, 고정 시그마, CFG 1)는 Cloud에서 결정적이다. 같은 플레이트, 프롬프트, 시드로 서로 다른 그래프에서 픽셀 동일한 결과가 나왔다. 2048×1536 실행 약 12초(2026-10-22).

## 6. 제한

- 폴더·데이터셋 이미지 로더가 없어 그래프 안에서 폴더 일괄 처리를 할 수 없다(2026-10-22).
- 완전 비압축 영상 파일은 받을 수 없다. 코어 EXR은 ZIP 압축이다(2026-11-09). 대안은 ProRes 4444 10bit, 16bit PNG 시퀀스, EXR 시퀀스다.
- 독립 실행 Python 도구는 Cloud에서 돌릴 수 없다(2026-11-08). 근사 그래프로 대체했으면 원본 도구보다 약하다고 적고 그 도구의 결과와 대조한다.

## 8. 저장과 색에서 나온 Cloud 동작

- 코어 `LoadVideo → SaveVideo` 색 경로는 BT.601·BT.709 태그 소스 모두 3레벨 이내로 측정됐다. 색이 바뀌면 입출력보다 모델과 프롬프트를 먼저 본다(2026-10-13).
- 코어 `SaveVideo`는 BT.709 태그와 CRF 18을 쓴다(2026-10-13). 홀수 가로·세로에서 실패하므로 저장 전에 짝수로 맞춘다(2026-10~11 작업 기록).
- Cloud `SaveImage`는 8비트로 내림 저장한다. 레벨 미만 이미지 연산은 약 0.5레벨 어두워진다. `ClampImage(img, 0.502, 0.502)`를 `FrequencyCombine`에 넣는 식으로 저장 전 +½레벨을 더하면 보정된다(2026-11-08).
- 코어 EXR은 입력을 `linear`로 저장하면 코드값이 유지된다(2026-11-09).
