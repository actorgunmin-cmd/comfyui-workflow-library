# 테스트 절차

사용자는 실제 테스트 여부를 반복해서 확인한다. 어디까지 검증했는지 구분하는 것이 이 문서의 핵심이다.

2. 정적 검증
3. 프런트엔드 왕복 검증
4. 로컬 CPU 모의 실행
5. Cloud 실제 실행

## 1. 검증 단계와 라벨

보고서에는 아래 라벨만 쓴다. 위 단계의 통과가 아래 단계의 통과를 뜻하지 않는다.

| 라벨 | 뜻 |
|---|---|
| 정적 통과 | `tools/validate_workflow.py` error 0. JSON 구조만 확인 |
| 왕복 통과 | 실제 프런트엔드에서 불러오고 `graphToPrompt`로 값 전달 확인 |
| 실행 완료 | Cloud에서 job이 끝났고 파일이 나옴. 품질은 판정하지 않음 |
| 시각 통과 | 전체 프레임을 보고 요구대로 바뀌었음을 확인 |
| 부분 성공 | 일부 프레임이나 일부 기능만 통과. 무엇이 통과인지 적음 |
| 실패 | 실행했고 요구를 못 맞춤 |
| 실행 불가 | Cloud에 노드나 모델이 없음. 정확한 노드명과 출처를 적음 |
| 미실행 | 시험하지 않음. 이유를 적음 |
| 사용자 요청 제외 | 사용자가 시험 대상에서 뺌 |

재생성 모델에는 완전한 픽셀 일치를 합격 기준으로 삼지 않는다(2026-09-27).

## 2. 정적 검증

```
python3 -I tools/validate_workflow.py <파일이나 폴더> [--json report.json]
```

이 도구가 보는 것은 다음과 같다.

- 링크 테이블과 입력·출력 포인터 일치, 슬롯 범위, 노드 id 중복.
- 그래프 안의 순환 참조.
- `widgets_values`와 `widgets_values_named`의 모델 이름 일치, 스텝·시드·CFG 불일치 경고.
- 중첩 서브그래프 정의 순서.
- JSON 좌표 기준 겹침, 안내 노트 존재, `properties.models` 누락.

사람이 더 확인할 것은 다음과 같다.

- 승격 위젯과 `widgets_values` 개수·순서(`references/노드_함정.md` 1절).
- 서브그래프 경계를 넘는 순환 참조. 도구는 그래프 안의 순환만 잡으므로 실제 프런트엔드의 `graphToPrompt`로 본다(2026-11-08에 승격 입력 링크 불일치로 순환이 생긴 파일이 있었다).
- 파일명, 메인 노드 제목, 저장 접두어가 가리키는 모델·기능과 실제 그래프의 일치. 안내문과 노드 제목과 실제 값의 일치. 값과 다른 제목은 2026-11-09 점검에서 가장 많이 나온 결함이다.
- 모델 이름이 Cloud 규칙을 따르는지. 바이패스된 노드와 꺼진 분기까지 본다.

## 3. 프런트엔드 왕복 검증

정적 검사와 자체 UI→API 변환기는 프런트엔드 전용 값 밀림을 놓친다(2026-10-14). 실제 프런트엔드로 확인한다.

Cloud 탭에서 하거나, 로컬에서 한다. 로컬은 `pip download comfyui-frontend-package==<Cloud에 가까운 버전> --no-deps`로 wheel을 받아 풀고, ComfyUI를 `main.py --cpu --front-end-root <풀린 폴더>/comfyui_frontend_package/static --user-directory <dir> --port 8200`으로 띄운다. 파일은 `<dir>/default/workflows/`에 두고 `app.loadGraphData(await (await fetch('/api/userdata/workflows%2F<이름>.json')).json())`로 불러온다.

1. `app.loadGraphData(json)`로 불러온다.
2. `await app.graphToPrompt()`의 `output`을 의도한 API 그래프와 노드·입력별로 비교한다.
3. 메인 노드 값을 기본값과 다른 숫자로 바꾸고 내부 API까지 전달되는지 확인한 뒤 되돌린다. 기본값만 비교한 재불러오기로는 밀림을 못 잡는다(2026-11-08).
4. `graph.serialize()`로 저장한 뒤 다시 불러와 API를 비교한다. 비교 전에 빈 `video-preview` 키를 정규화한다.
5. 렌더된 값으로 겹침을 검사한다. `app.graph`의 pos, size에 제목 30px를 더한 사각형을 쓴다. 서브그래프 내부도 본다.
6. 처음 보이는 화면을 실제 스크린샷으로 확인한다. 쓸모 있는 위치에 열리는지, 제목이 잘리지 않는지, 수천 픽셀짜리 빈 공간이 없는지 본다.

배치만 고쳤다면 전후 `graphToPrompt` 동일성으로 끝낸다. GPU 재생성은 필요 없다(2026-11-08).

납품 파일이 시험한 파일과 같음을 증명해야 하면, 같은 JS 처리 코드를 로컬 Node와 Cloud 탭에서 돌려 출력 SHA256을 비교한다(2026-11-08).

## 4. 로컬 CPU 모의 실행

모델 없이 기하, 프레임 수, FPS, 오디오를 확인하는 방법이다(2026-10-13, 8GB 환경에서 동작).

1. ComfyUI와 VHS, KJNodes, 필요한 팩을 얕게 클론하고 `main.py --cpu --cache-none`으로 띄운다.
2. `/object_info`를 받는다.
3. 3절에서 얻은 `graphToPrompt().output`을 API 그래프로 쓴다. 자체 변환기는 프런트엔드 전용 밀림을 놓치므로 새로 만들지 않는다.
4. VAE 디코드를 가이드 프레임으로 대체하고 모델 노드를 잘라낸다. 이것이 "모의 생성"이다.
5. 실행해서 프레임, 크기, FPS, PSNR을 원본과 비교한다. 실제 360p 클립의 코덱 한계는 약 43~44dB이다. testsrc2 합성 패턴은 약 24dB로 낮게 나오는데 정렬 문제가 아니다.

프레임은 40장, 해상도는 360p~480p 이내로 한다. 그 이상이면 메모리 부족으로 서버가 죽는다. 모의 실행은 품질을 증명하지 않는다. 라벨은 '왕복 통과'에 부가 설명으로 적는다.

## 5. Cloud 실제 실행

### 준비

- 워크플로를 만들면 불러오기 확인에 그치지 말고 생성까지 돌린다(2026-11-05). 수정한 파일도 다시 돌린다(2026-10-21).
- 전체 라이브러리 납품 전 점검은 파일을 하나씩 살피고, GPU 실행은 필요해 보이는 파일을 골라 한다(2026-11-09). 나머지는 '미실행'으로 적는다.
- 기존 성공은 설정과 증거가 일치할 때만 재사용한다(2026-11-07).
- 사용자가 준 크레딧 범위와 사용량 상한 안에서 돌린다. 유료 파트너 노드는 사용자 승인 없이 돌리지 않는다.
- 유료 API와 스토리보드 계열은 시험 대상이 아니다(2026-11-08). 폴더 이름이 아니라 중첩 서브그래프 안의 실제 노드로 판단한다.

### 순서와 크기

- 가벼운 파일부터 돌리고 WAN 같은 무거운 파일은 뒤로 미룬다. 동시 실행이 1건이기 때문이다(2026-10-22).
- 동작 확인은 크기를 줄여 크레딧을 아끼고, 화질 판정은 실제 작업 크기로 한다(2026-10-23~2026-11-01).

### 소스와 프롬프트

- 작업 유형에 맞는 소스로 시험한다. 사용자가 준 소스와 참고 이미지를 빼먹지 않는다. 교체 VFX는 편집된 첫 프레임을 쓴다(2026-10-21~23).
- 사용자가 이번 시험용으로 주지 않은 소스는 공개·비노골적 자료만 쓴다. 공개 샘플에 미공개 소스를 넣지 않는다.
- H3와 LTX는 다양한 영상과 참조 이미지로 시험한다. 클립 1개 결과를 일반화하지 않는다(2026-11-08).
- 프롬프트는 워크플로 용도에 맞게 직접 쓴다. 기본 자리표시 프롬프트로 판정하지 않는다.
- 원본과 참조가 같으면 비교가 안 된다. 눈에 띄는 변경으로 시험한다. 사진 참조가 안 먹으면 사진을 고쳐 재시도하고, 사진을 안 받는 경로는 프롬프트로 시험한다(2026-11-07).
- 어두워지는 편집도 시험한다. 차이 보호 합성의 한쪽 방향 결함은 밝은 플레이트에 어두운 편집일 때만 드러난다(2026-10-14).
- 외부 툴을 대체하는 워크플로는 그 툴의 결과와 대조하며 맞춘다(2026-10-21~23).
- 문제가 있던 파일은 알파를 직접 뽑아 넣고 마스크 폭과 페더를 바꿔 가며 실험한다(2026-10-22).

### 실행

Cloud 조작 방법은 `references/클라우드_사실.md` 4절과 5절에 있다. 진행 상황은 `/jobs/{id}`로 본다. 실행된 프롬프트는 `/history_v2/{prompt_id}`나 출력 MP4의 메타데이터에서 확인하고, 저장한 JSON과 대조한다. 파일 이름이 맞다는 이유만으로 모델이나 LoRA가 적용됐다고 판단하지 않는다(2026-09-27).

## 6. 원본 대비 측정

눈대중만 하지 않고 숫자를 함께 쓴다(2026-10-21, 2026-11-08). 측정 안 한 항목은 '미측정'으로 적는다.

| 항목 | 방법 | 기준 |
|---|---|---|
| W×H, 프레임 수, FPS | `ffprobe`, 또는 job 메타데이터의 `width`, `height`, `frame_count`, `fps` | 원본과 정확히 같다. 29.97은 표기 차이를 허용. 규격을 바꾸는 기능은 그 항목 제외 |
| SAR/DAR, 회전 메타데이터 | `ffprobe` | 표시 비율이 같다 |
| 가변 FPS, 프레임 누락·중복 | `ffprobe`의 프레임별 시각, 프레임 비교 | 원본과 대응이 일정하다 |
| 편집 이미지 방향·여백 | EXIF 방향, 이미지 안 여백 | 원본 프레임과 같은 좌표계다 |
| 시간 정렬 | 프레임별 움직임 곡선의 상관과 최적 오프셋 | 오프셋 0. LTX Ripple은 1..N을 썼는지 |
| 움직임 유지 | 위 상관값. 줌하는 장면은 몇 프레임 차이가 확대처럼 보이므로 같은 시점끼리 비교 | 2026-10-22 사례: 0.06 → 0.94 |
| 고정 영역 보존 | 원본 기반 마스크나 얼굴·손 영역에서 MAE, PSNR | 낮은 차이. 평가 영역을 출력 차이로 정하지 않는다 |
| 색 | 채널별 평균 차이, 저주파 차이(영역별) | 수정 대상 밖은 변화 없음 |
| 레퍼런스 반영 | 교체 영역의 색·형태를 레퍼런스와 대조 | 첫 프레임뿐 아니라 끝까지 유지 |
| 편집 유지율 | 첫 프레임 대비 편집이 프레임별로 남은 비율 | 후반에 원본으로 돌아가지 않는다 |
| 디테일 | 원본 대비 선명도, 저주파 차이 | 업스케일은 많이 바뀌지 않는다 |
| 경계 | 마스크 경계 확대 이미지 | 잔여물, 번짐, 계단 없음 |

- 고정 영역은 원본 기반 마스크로 잰다. 출력 차이로 평가 영역을 정하면 원치 않는 변형이 평가에서 빠진다. 그렇게 쟀다면 한계를 밝힌다(2026-11-08).
- 전체 프레임을 확인하고 교체 유지, 잔류, 손 가림, 후반 복귀, 새 물체, 색감, 구도를 본다(2026-11-08).
- 비교 프레임은 시작, 중간, 컷 직전, 컷 직후, 끝을 포함한다. 시험 클립의 구조는 프레임 간 차이로 측정한다. 하드컷을 줌으로 착각하지 않는다(2026-11-08).
- 비교 화면이 자동으로 맞춰 확대되는지, 실제 기하 변화인지 선명도 차이인지 구분한다(2026-09-27).
- 확대처럼 보이면 샘플링 변화와 디코딩 변화를 나눈다. 같은 latent를 다른 디코드 설정으로 짧게 비교하고, 저장 전 이미지와 저장 후 영상의 같은 프레임을 비교한다(2026-09-27).
- '최고 화질'이라는 이름보다 원본 대비 구도, 피사체 크기, 움직임, 시간 정합성이 유지되는지를 우선한다(2026-09-27).
- 교체 성공이 리무브 성공을 뜻하지 않는다. 기능별로 따로 판정한다(2026-11-08).
- 측정 조건을 항상 함께 적는다. 입력 W×H, 프레임 수, FPS, 추론 해상도, 패딩 길이, 보간 확대 여부, 시드, 스텝.

## 7. 한 변수 A/B와 대조 실험

- 같은 시드, 입력, 모델, 강도에서 주요 변수를 한 번에 하나씩 바꾼다(2026-09-27).
- 프롬프트 문장만 바꾼 비교부터 시작한다. 그래도 안 되면 원인에 맞는 설정을 바꾼다. 의미 없는 무한 재시도는 하지 않는다(2026-11-08).
- 스텝을 줄이는 변경은 같은 영상, 같은 시드로 기존과 비교한다(2026-11-07). 측정상 같으면 가벼운 쪽을 택한다.
- 편집 이미지 대신 원본 첫 프레임을 넣는 대조 실험으로 경로 자체의 변형을 가려낸다(2026-09-27).
- 모델 교체 A/B는 새 복사본에서 하고, 파일과 강도, 레시피를 분리해서 본다. 고저 노이즈 쌍은 함께 바꾼다.
- 결과는 확정 결함, 원인 후보, 추가 확인 필요로 나눈다.
- Qwen 2.1 Turbo처럼 결정적인 모델은 A/B의 잡음이 없다. 픽셀 동일성으로 경로 차이를 판단할 수 있다(2026-10-22).

## 8. 증거 남기기

실행 증거로 다음을 축약 없이 남긴다(2026-11-08).

- 전체 job ID.
- 실제 인코더에 들어간 문장.
- 입력 자산 식별자.
- 전체 출력 파일명.
- 대표 결과와 비교 이미지.

스크린샷에는 계정 메뉴나 이메일이 보이지 않게 한다. 실행 ID 같은 증거는 내부 보고서에만 두고 공개본에는 넣지 않는다.

다른 검수자가 없으면 혼자 판정한 사실과 확인한 프레임 수를 적는다(2026-11-08). 독립 검수가 가능하면 맡긴다. 2026-11-08 독립 검수는 승격 입력 순환 참조, Cloud에 없는 기본 모델, 증거 식별자 부족을 찾아냈다.

## 9. 파일별 체크리스트

대표 몇 개가 아니라 파일 하나하나를 본다(2026-11-01, 2026-11-07). 끝나면 전체를 다시 한 번 최종 점검한다(2026-10-13).

- [ ] 메인 서브그래프 1개, 입력·저장은 밖, 사람이 바꾸는 값만 노출
- [ ] 시드 1개
- [ ] 위젯 라벨 한국어, 안내 노트 2종, `properties.models` 완비
- [ ] 코어·사전 설치 팩만 사용, 모델 이름이 Cloud 규칙에 맞음
- [ ] 해상도 왕복(원본 → 추론 → 원본), 크롭·늘림 없음
- [ ] 프레임·FPS 수식, 짧은 영상, 규칙 밖 길이, NTSC FPS, 시작 시점을 바꿨을 때 편집 이미지가 그 구간 첫 프레임과 맞는지
- [ ] 패딩 후 자르기, 시간축 오프셋
- [ ] 마스크 방향, 반전 스위치 기본 꺼짐, 생성·합성이 같은 마스크 사용
- [ ] 합성 경계, 보호 구역 원본 일치
- [ ] 스위치 기본값, 비선택 분기 모델 존재
- [ ] 수식 오류, 변수명 a부터 연속
- [ ] 샘플러·LoRA 정합성, LoRA 중복 없음, 제작자 권장과의 차이
- [ ] 기본 프롬프트가 완성된 문장이고 접두사가 맞음
- [ ] 제목·안내와 실제 값 일치, 옛 안내 없음
- [ ] 기본 출력 무음(소리를 쓰는 파일은 생성 효과음 꺼짐), 오디오 트랙 없는 소스에서 멈추지 않음
- [ ] 저장 1개, 저장 접두어와 메인 제목이 파일의 모델·기능을 가리킴
- [ ] 레이아웃 그룹·색, 겹침 0, 그룹 밖 노드 0, 15의 배수
