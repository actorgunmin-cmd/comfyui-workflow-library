# 노드 함정과 정확성 사실

정적 검사로 잡히지 않고 조용히 결과를 망치는 동작을 모았다. 괄호에 확인 날짜와 근거를 적었다. "소스"는 ComfyUI나 해당 노드팩의 소스 코드를 읽어 확인했다는 뜻이고, "측정"은 실제 실행으로 확인했다는 뜻이다.

## 목차

1. JSON과 프런트엔드
2. 리사이즈와 크롭
3. 프레임 수와 FPS
4. 마스크
5. MiniMax H3
6. LTX
7. WAN
8. 합성, 색, 저장
9. 기타 노드

## 1. JSON과 프런트엔드

| 함정 | 결과 | 대응 |
|---|---|---|
| 노드에 `widgets_values_named`가 있으면 Cloud 프런트엔드가 먼저 읽는 경우가 있다 | 스텝 28→4 패치가 28로 남았다(측정 2026-11-07) | 값을 고칠 때 `widgets_values`와 둘 다 고치고 Cloud에서 실제 적용값을 확인한다 |

| 끝쪽 값이 모자란 경우 | 해롭지 않다. 안쪽 위젯 값으로 돌아간다(2026-10-14) | 뒤쪽만 비는 경우에 한한다 |
| 서브그래프 A가 B를 포함하는데 `definitions.subgraphs`에서 B가 뒤에 있다 | B 인스턴스 값이 사라지고 내부 기본값으로 돌아간다(2026-10-23, 프런트 1.57.1) | B를 A보다 앞에 둔다. `tools/validate_workflow.py`가 이것을 잡는다 |
| 정의 간 내부 노드 id가 겹친다 | 불러올 때 번호가 바뀐다(2026-10-23) | 스크립트로 만든 노드는 고유 id를 준다 |
| 레거시 `properties.proxyWidgets`와 링크 승격을 한 노드에 섞는다 | 값이 어긋난다(2026-10-14) | 섞지 않는다. 노드를 교체할 때 사라진 위젯을 가리키는 항목을 지운다 |

| 다이내믹 콤보를 가진 노드(`RTXVideoSuperResolution`의 `resize_type`, `GeminiVideoOmniV2`의 `model`) 승격 | 다른 위젯 값이 밀린다(2026-11-08) | 최상위에 두거나 승격하지 않는다 |
| autogrow가 다이내믹 콤보 안에 있는 노드에 위젯 입력을 손으로 추가 | 링크가 사라진다(2026-10-14) | 프런트엔드에서 연결하고 `graph.serialize()`로 저장한다 |
| `convertToSubgraph` | 동적·autogrow 입력 연결을 망가뜨릴 수 있다 | 변환 전후 `graphToPrompt`를 비교한다 |
| 최상위에서 바이패스(mode 4)한 `LoadImage` | 링크를 끊어 그것만 연결된 선택 입력은 None이 된다. 선택 입력에 이용할 수 있다(2026-10-14) | 전송용으로 줄일 때 `mode`를 지우지 않는다 |
| 이미지를 고르지 않은 `LoadImage`가 켜져 있다 | 검증 오류 | 선택 입력은 뮤트하거나 지운다 |

| `VHS_LoadVideo`를 dict `widgets_values`로 저장할 때 `'choose video to upload'` 키가 없다 | 값이 밀려 `No frames generated`가 난다(2026-10-05) | 키를 넣는다. 값은 `'image'`다 |
| Cloud 프런트엔드의 위치 처리 | 15px 격자에 맞추고 크기를 올림한다(측정 2026-11-08) | 15의 배수로 배치하고 겹침은 렌더된 좌표로 본다 |

## 2. 리사이즈와 크롭

- `ResizeImageMaskNode`의 `scale to multiple`은 늘이기가 아니라 cover 후 중앙 크롭이다(1080→1056, 소스 2026-10-13). 키는 소문자(`match size`)이고 위젯은 `resize_type`, `crop`, `scale_method`이며 `scale_method`에 `disabled`는 없다(2026-11-09).
- `lanczos` 리사이즈는 8비트 PIL을 거쳐 양자화하고 0~1로 자른다. HDR, ACEScct, 로그 데이터에는 bicubic이나 area를 쓴다(소스 2026-10-13). `ImageScale`은 크기가 같아도 lanczos를 호출한다(소스 2026-11-09).
- SDR 경로에서 lanczos를 bicubic이나 area로 바꾸면 디테일이 준다. 전처리부터 저장까지 로컬 측정에서 원본 대비 104.6%가 92.3%로 떨어졌다(2026-10 측정).
- `VHS_LoadVideo`의 format은 원본 규격 유지에 `None`을 쓴다. `LTXV`는 프레임을 8n+1로 잘라 끝을 잃고 크기를 32배수로 늘린다. `AnimateDiff`는 8배수로 중앙 크롭한다(854×480→856×480, 2026-10-13).
- ComfyUI 메가픽셀은 1024² 기준이다. 16:9에서 1024×576은 0.56이고(0.59는 1056×576), 576×1024는 0.5625다(0.59는 592×1056, 측정 2026-11-08).
- 원본과 편집 이미지에 같은 좌표 변환을 적용한다. 서로 다른 경로로 리사이즈하면 확대되어 보일 수 있다(2026-09-27).
- `SaveVideo`는 홀수 크기에서 실패한다. 저장 전에 짝수로 맞춘다(2026-10~11 작업 기록).

## 3. 프레임 수와 FPS

- FPS 일치 검사의 허용 오차는 `abs(c - d) < 0.0001`로 둔다. `GetVideoComponents`는 `float(Fraction)`을 돌려주고(23.976023976) `SaveVideo`는 3자리로 반올림한다(23.976). 차이가 2.4e-5라 `1e-6` 검사는 NTSC 영상에서 멈춘다(소스 2026-11-09, 실제 NTSC 클립으로 돌리지는 않았다).
- '멈춤' 구현은 `ComfyMathExpression`의 0 나눗셈이다. 마스크 파일 예: `a if (b >= a and abs(c - d) < 0.0001 and abs(e / f - g / h) < 0.01) else 1/0`(프레임 수, FPS, 종횡비). H3 길이 패딩 예: `max(5,5+17*ceil(max(0,a-5)/17)) if 1<=a<=362 else 1/0`. `division by zero`는 이 가드일 수도, 전송 때 노드 `mode`를 지워 바이패스 노드가 켜진 것일 수도 있다(`references/클라우드_사실.md` 4절).
- 코어 `FrameInterpolate`의 출력 프레임 수는 `(N−1)·m+1`이다(2026-10-13).
- 코어 `Video Slice`의 `duration`은 0이 무제한이다. 0이 아닌 기본값은 긴 영상을 조용히 자르고, 뒤따르는 N, W, H 계산도 잘린 영상을 따른다(소스 2026-11-09).
- 코어 `VideoFrameSample`(uniform, `num_frames` ≤ total)은 파일 기반 VIDEO의 시간을 무손실로 바꾼다. 메모리 영상은 다시 인코딩된다(2026-10-13).
- `VideoFromComponents`에 `Video Slice`를 걸면 H.264로 한 번 인코딩한 뒤 `SaveVideo`가 다시 인코딩해 손실이 두 번 생긴다(소스 2026-11-09, 손실량은 재지 않았다). 파형 길이는 `save_to`가 이미 맞춘다.
- `ImageExpandBatch+`는 개수를 강제한다. 그 뒤에 둔 프레임 수 검사는 항상 통과한다(2026-11-09).
- 소스에 오디오 트랙이 없으면 `VAEEncodeAudio`가 `input audio is None`으로 멈춘다. 오디오 경로는 트랙 존재 여부로 분기한다(2026-09-26, 2026-10-04 실제 오류).
- 모델 규격에 맞추려고 끝을 패딩하고 생성 후 자르면, 끝 프레임을 고정하는 입력의 효과도 같이 잘린다. 고정된 프레임은 패딩된 마지막 위치에 있어서 자를 때 버려진다(H3 예, 소스 2026-11-09).

## 4. 마스크

- 영상 압축 때문에 마스크의 흰색은 정확히 1이 아니다. 반전 후 `BlockifyMask`를 쓰면 화면 전체가 마스크가 될 수 있으므로 반전 경로에 0.5 이진화를 넣는다(2026-10-14).
- `GrowMask`는 흰 영역을 넓힌다. 흰색이 배경인 마스크에서는 인물 안쪽을 파먹는다(2026-10 작업 기록).
- 코어 `FeatherMask`는 마스크 윤곽이 아니라 프레임 테두리 쪽으로 페이드한다(소스 2026-11-09).
- `MaskSmooth+`는 먼저 0.5로 임계 처리해 앞선 페더를 지운다(소스 2026-11-09).
- KJ `GrowMaskWithBlur`의 `decay_factor`를 1 미만으로 하면 프레임별 최대값 정규화가 된다. 1.0이면 꺼진다(소스 2026-11-09).
- `ImagePadForOutpaint`는 1프레임 마스크를 돌려준다. 영상 프레임 수 마스크와 합치려면 먼저 프레임 수만큼 늘린다(2026-10 작업 기록).
- `LoadImage`의 투명도는 MASK 출력으로만 나온다. 투명 PNG는 그 MASK로 합성한다(2026-11-01).
- `SAM3_TrackToMask`의 `object_indices`가 `'0'`이면 첫 추적 대상만 마스크하고 빈 값이면 전체다. person 마스크에는 손에 든 물건이 포함되지 않는다(측정 2026-11-08).
- AlphaGen은 RGB 입력만 받고 마스크 입력을 지원하지 않는다. 특정 대상만 뽑으려면 SAM 마스크와 합성 단계에서 합친다(모델 카드 2026-10-30).

## 5. MiniMax H3

- 규격은 24fps, 17k+5 프레임, 32배수 캔버스다. 학습 크기는 짧은 변 약 768, 768×1344다(2026-10-13).
- `MiniMaxH3AddGuide`는 여러 프레임 가이드를 17k+5로 내림하고, 이미지를 latent 크기로 중앙 크롭한다(소스 2026-10-14). 2패스 정제에는 원본 프레임을 2패스 W×H로 정확히 늘려서 넣는다. 1패스 크기 가이드는 흐린 앵커가 되어 없는 디테일을 만든다.
- `MiniMaxH3ImageToVideo`는 `first_frame`은 늘이고 `last_frame`은 cover 크롭한다. 같은 이미지를 양쪽에 넣어도 기하가 달라진다. `last_frame`은 `frame_count-1`에 고정되므로 원본이 17k+5 프레임일 때만 패딩 없이 끝 프레임이 남는다(소스 2026-11-09).
- `ref_videos`는 시간에 고정되지 않는 참고 입력이고 `AddGuide`는 프레임 정렬 가이드다. 원본 흔들림과 시간축 유지가 필요한 VFX에는 `AddGuide`를 쓴다(2026-10-14).
- `AddGuide`에 원본 전체를 넣어도 가이드 학습 LoRA(`vfx_edit`, `head_swap`, `style_transfer`, LMS, character swap의 `body_swap`)가 켜져 있어야 편집된다. 없으면 원본이 거의 재현된다(2026-10-14). "Singularity면 LoRA 강도 0"이라는 안내는 틀린 것이다.
- `h3_character_swap_pro4500_1000`과 CrossView-Warp는 `<Video 1>` 참고 방식이고 시간에 고정되지 않는다(2026-10-14).
- FFP(`vfx_edit_v1.0_r128_ffp`)는 576×1024 입력 시험에서 0.26MP, 124프레임 이상 패딩일 때만 전파됐다. 0.52MP와 1.03MP는 변화가 없었다(측정 2026-11-08). 이 조건 밖으로 일반화하지 않는다.
- FFP 구성은 편집 프레임을 `ref_image_0`에 넣고 가이드 0번 프레임도 교체하는 것이다(제작자 그래프 2026-10-14). 측정 1건에서 프레임 오프셋은 0이고 편집은 잘 전파됐지만, 나머지 영역은 전역 색 틀어짐과 함께 재생성됐다. 차이 보호 합성으로 복원했다.
- Singularity 1.3 + FFP LoRA는 플레이트 샷 Cloud 실행에서 가이드의 움직임은 따랐지만 수정 이미지를 따르지 않았고 어두운 저녁 조명으로 바뀌었다. 기본 ref2va + FFP는 따랐다(2026-10-14, 시험 1건씩).
- 잠긴 플레이트(흔들림 2px 이내)에서 수정 첫 프레임이 있으면 결정적 합성이 AI보다 나았다(2026-10-14, 시험 1건).
- H3 기본 Sigma shift는 12/3이다(2026-10-22). fl2v 8스텝 768p는 6/3이다(2026-11-07).
- Turbo 구성(Cloud A/B 2026-11-07, 576×736, 124프레임, 같은 시드): ref2v Turbo 4스텝 Sigma 12/3은 안내 편집과 ControlNet 아웃페인팅에서 28스텝과 같거나 나았고 약 4배 빨랐다. fl2v 4스텝 v1.3은 자유 생성 프레임이 무너졌다. fl2v 8스텝 v1.1 768p Sigma 6/3은 28스텝과 비슷하고 약 2.7배 빨랐다. v1.3을 Sigma 12로 돌리면 피사체가 바뀌었다.
- Pika H3 Flex Ref2VA는 코어 `MiniMaxH3ReferenceToVideo`의 `ref_videos.ref_video_0`에 원본을 넣고 프롬프트에서 `<Video 1>`로 지칭하며, 6스텝 `lcm` + `ManualSigmas`를 쓰고 LoRA를 더하지 않는다. 물체 교체는 제품 사진 한 장으로 충분했다(2026-11-08).
- reference video가 2초보다 짧으면 17n+5 규격의 48프레임 이상으로 패딩하고 디코드 후 자른다(2026-11-08).
- 하드컷이 있는 영상의 리무브를 전체 한 번에 생성하면 컷이 1프레임 늦게 나왔다(시험 클립 1건, 2026-11-08).
- 마스크 컷별 + Pika 6스텝 구성은 형태가 비슷한 사물 교체 클립에서는 좋았지만(머리·손 차이 1.3~2.0) 다른 단일 샷 클립에서는 4회 모두 실패해 회색 잔여물이 남았다(2026-11-08).
- H3 인페인팅에서 `Remove the ...` 문구는 새 인물을 만들었고, 남은 빈 장면만 묘사하면 제거됐다(시험 클립 1건, 2026-11-08).
- 근접 인물은 PersonRemover로 실제 클린 플레이트를 줘도 다른 인물로 바뀌었다. 멀리 있는 1명까지만 된다(2026-11-08).
- H3 오디오는 24fps 시간축이다. 다른 FPS 원본은 효과음과 화면이 맞지 않는다(소스 2026-11-09, 실제 어긋남 양은 재지 않았다).
- 2패스 시도의 'over-detail' 문제의 원인은 latent 파일이 아니라 2패스에 원본 가이드를 다시 넣지 않은 것이었다(소스 2026-10-14). 색 틀어짐이 해결됐다는 실측은 없다.

## 6. LTX

- `LTXVCropGuides`는 전달받은 conditioning이 나열한 만큼 latent 프레임을 잘라낸다. 1단계 conditioning을 2단계 latent에 넣으면 실제 프레임 8장이 줄어든다(2026-10-13).
- 코어 `LTXVAddGuide`는 가이드 latent를 덧붙이므로 `LTXVCropGuides`를 latent 업스케일과 디코드 전에 둔다(2026-10-05).
- `LTXVLatentUpsampler`는 `noise_mask`를 버린다. 2단계 연장에서는 ImgToVideoInplace로 컨텍스트 전체를 다시 고정한다. 안 하면 0번 프레임만 실제로 남는다(2026-10-13).
- `LTXVDilateVideoMask`는 출력을 0.5로 임계 처리한다. 임계 먼저, 팽창은 나중에 한다(2026-10-13).
- `LTXAddVideoICLoRAGuide`의 `frame_idx -1`은 첫 프레임 앞 슬롯이고, 코어 `LTXVAddGuide`의 -1은 마지막 프레임이다(2026-10-13).
- LTX Ripple(FFAF)은 편집 프레임을 앞에 붙이므로 출력 k가 원본 k−1에 대응한다(측정 상관 0.997). 한 프레임 더 생성해 1..N번을 쓴다(2026-10-13). 편집 이미지는 처리 구간의 첫 프레임이어야 하고 원본 0번일 필요는 없다.
- EditAnything은 텍스트 전용으로 사진 참조를 직접 받지 않는다. 색 변경이 안 되거나 의상을 다른 디자인으로 바꾼 시험이 있다(2026-11-08).
- LTX 인페인팅 리무브는 프롬프트가 있으면 검게 나왔고 빈 프롬프트에서는 일부 시험에서 동작했지만 다른 시험에서 초록 덩어리가 남았다. 안정적이지 않다(2026-11-08).
- 마스크 합성 클린 플레이트는 합성 경계가 결과에 비쳤다. 합성하지 않은 생성 플레이트에서는 나타나지 않았다(시험 클립 1건, 2026-11-08).
- LTX 프롬프트 인핸서 경로는 라이브러리 기본에서 꺼져 있다. 스위치의 on_true가 lazy라 인코더가 실행되지 않는다(소스 2026-11-09).

## 7. WAN

- `WanVaceToVideo`의 reactive는 control_video × mask, inactive는 control_video × (1−mask)다. 마스크 안 회색 0.5는 모션 정보가 없어 동작을 새로 만든다(2026-10-13).
- 포즈와 윤곽을 넣을 때는 검정 바탕이 아니라 회색 위 선으로 합성한다. 검정 바탕 맵은 Cloud 시험에서 결과를 어둡게 했다(2026-10-13). 마스크 안을 흰색으로 채우면 결과가 밝은 쪽으로 기운다(2026-10~11 작업 기록).
- 더 강한 모션 고정은 `KSamplerAdvanced`를 소스 latent에서 시작하는 것이다. `ReplaceVideoLatentFrames`로 VACE latent의 trim_latent 위치에 넣고 `start_at_step = steps×(1−denoise)`로 둔다(2026-10-13). 선택 옵션으로만 넣는다.
- WAN VACE 노드는 참고 이미지를 영상 비율로 중앙 크롭한다. `ResizeAndPadImage`로 먼저 맞춘다(2026-11-01).
- WAN2.1 VACE 교체는 참조가 흰 배경의 의상 단독이고 마스크 확장이 8일 때 카메라 줌에서도 유지됐다. 전체 수정 프레임을 참조로 쓴 경우보다 나았다(시험 1건, 2026-11-08).
- 2.2 Lightning 파일은 rank와 alpha가 달라 같은 강도라도 실제 세기가 다르다(2026-11-09). `references/모델_최신확인_절차.md`를 본다.

## 8. 합성, 색, 저장

- 코어 `ImageBlend`의 `difference`는 한쪽 방향이다(`clamp(img1 − img2, 0, 1)`). 어두워진 변경이 0으로 읽혀 원본으로 덮인다. 절댓값 차이는 `Blend(src, gen)`, `Blend(gen, src)`를 `screen`으로 합쳐 만든다(소스 2026-10-14). 시험은 밝은 플레이트에 어둡게 바꾸는 편집으로 한다. numpy 모의 실험의 `abs()`가 이 결함을 가렸다.
- 차이 보호 합성(1/8 차이, 임계 0.15, 확장 2)은 교체 대상을 살리고 나머지를 원본으로 복원했다(측정 1건, 2026-10-14).
- AI로 편집한 스틸은 전체 프레임이 다시 그려지므로 단순 |수정본−원본| 매트에는 원래 인물의 잔상이 남는다(2026-10-14).
- `ImageColorMatch+`의 `reference_mask`는 레퍼런스 통계만 제한한다. 대상 통계는 전체 프레임이다(소스 2026-11-09).
- KJ `ColorMatchV2`의 `hm-mvgd-hm`이 9가지 방식 중 LOG 색 맞춤이 가장 정확했다. 의상 전체처럼 큰 영역을 바꾸면 통계가 옛 색을 따라가 오차가 커진다. 선택 마스크 붙이기로 안 바꾼 영역이 0.014/255로 유지됐다(2026-11-09).
- CFG 1에서는 네거티브 프롬프트가 계산되지 않는다. CFG가 1보다 크면 스텝마다 모델을 두 번 돌린다.
- LoRA 가중치는 파일 이름이 맞아도 적용이 보장되지 않는다. 로딩 경고의 missing, unmatched keys를 확인한다(2026-09-27).

## 9. 기타 노드

- core `RegexReplace`로 `21:9` 같은 비율 문자열을 계산식으로 바꿀 수 있다(2026-10 작업 기록).
- `LoadLatent`는 `latent_format_version_0`이 없는 파일에 ×(1/0.18215)를 적용한다(2026-10-14). ComfyUI가 아닌 곳에서 만든 latent를 넣을 때 주의한다.
- 객체 추적 영상 마스크는 코어 `SAM3_VideoTrack` + `SAM3_TrackToMask`를 쓴다(2026-11-09). Impact는 `.pt` SAM2 파일명만 SAM2로 취급한다.
