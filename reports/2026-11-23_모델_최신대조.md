대상: 이 저장소 `workflows/`의 워크플로(공개 48개 + 공개하지 않는 12_NSFW 3개). 12_NSFW 전용 성인 카테고리 모델과 그 변형 파일은 공개 저장소에 포함하지 않아 이 보고서에서 뺐습니다.

## 0. 먼저 알아야 할 것: 라이선스

검증 에이전트가 각 LICENSE 원문에서 확인한 사실입니다. 법률 조언이 아닙니다.

- **MiniMax H3 Community License**는 Excluded Territories로 **EU, 영국, 대한민국, 미국**을 명시합니다. 이 라이브러리의 H3 기반 파일 전부(H3 본체, 터보, 커뮤니티 LoRA)에 적용됩니다.
- **P-H3-Image / P-Image-OSS**(PrunaAI)와 **MiniMax-H3-Image**도 대한민국을 제외 지역으로 적습니다. MiniMax-H3-Image는 매출 100만 달러를 넘거나 호스팅 서비스로 쓰면 별도 허가가 필요합니다.
- **H3 Person Remover**(akatz-ai)의 README도 미국, EU, 영국, 대한민국을 제외합니다.
- Qwen-Image 2.1 계열은 qwen-research(비상업) 라이선스입니다.
- 상업용이나 한국 기반 작업에서 라이선스 걱정이 적은 대안은 **MOSS-Image**와 **Z-Image-Turbo**(Apache-2.0)입니다. LTX-2.5는 Lightricks 라이선스 조건을 따로 확인해야 합니다.

## 2-1. 추가: H3 모션 전이 + 배경 교체 (코어 전용 · Guide Latents)

`11_스타일·모션FX/06_H3_모션전이+배경교체_GuideLatents_코어전용_Turbo8_미실행.json` (Comfy Cloud 실행 안 함)

- **TARA 판은 뺐습니다.** 핵심 노드 `BFSMiniMaxH3NativeTemporal`(ComfyUI-BFSNodes)이 Comfy Cloud에서 돌지 않는 것을 사용자가 확인했습니다. 제작자의 다른 공식 방식인 **Guide Latents**(Motion Transfer v1.0 LoRA, 원본을 AddGuide frame 0으로)로 다시 만들었고, 코어 노드만 씁니다.
- **용도**: 원본 영상의 움직임·타이밍·구도·카메라를 따라가며 배경(<Picture 2>)과, 필요하면 인물(<Picture 1>)을 바꿉니다.
- **기본 동작**: 원본 첫 프레임이 자동으로 <Picture 1>(인물)이 되므로 배경 사진만 넣으면 됩니다. 다른 인물을 쓰려면 ③ 인물 사진을 켜고 '인물 사진 직접 사용' 스위치를 켭니다.
- **구성**: H3-03 그래프 기반(크기·길이 자동화, 원본 W×H·N·FPS 복원 유지). ref2va + ref2v Turbo 8스텝 v1.0 768p + Motion Transfer v1.0(Alissonerdx). 12/3, euler, simple, CFG 1, 8스텝, 0.4MP, 사진은 1MP + `max`.
- 폐지 예정 경고가 뜨는 `ImageBatch`는 `BatchImagesNode`로 바꿨습니다. 원본 라이브러리 29개 파일에도 `ImageBatch`가 있습니다(지금도 동작함).
- 제작자 문서상 TARA는 여러 인물·사물에 더 낫고, Guide Latents는 사진 1장 이상이 움직임을 따라 하는 용도입니다. 여러 명이 동시에 나오는 장면은 결과가 약할 수 있습니다.
- 확인: 링크, 위젯 순서, 스키마(코어 v0.45.6), 노드 배치, LoRA URL. 앞선 TARA 판 검토에서 찾은 문제(배경 끄기 검사, 그룹·노드 id, 레이아웃)를 처음부터 반영했습니다.

## 5. 검토 후 만들지 않기로 한 것

추가 요청으로 세 파일을 더 만들었고, 독립 검토(에이전트 10개)를 거친 뒤 아래 두 개는 넣지 않았습니다.

1. **01/03_H3_R2V_글로편집_Turbo4에 시프트 노드 추가**: 넣지 않았습니다. 코어 v0.45.6의 H3 기본 시프트가 이미 12/3이라(`supported_models.MiniMaxH3.sampling_settings`), 노드를 넣어도 결과가 원본과 똑같습니다. 원본 파일은 규칙 위반이 아닙니다. 앞선 보고에서 위반이라고 한 것은 틀렸습니다.
2. **03/03 PersonRemover 창 분할 변형(코어 `MiniMaxH3ContextWindows`)**: 넣지 않았습니다. 코어 창 분할은 정렬 가이드(AddGuide)만 창마다 잘라 주고, 초록 마스크 참조 영상(`<Video 1>`)은 모든 창에 전체 길이 그대로 들어갑니다. 그래서 두 번째 창부터 참조 영상과 가이드의 시간이 어긋나 결과가 틀어질 수 있습니다. 제작자 방식(창마다 참조 영상을 잘라 주고, 앞 창 결과를 이어 붙이는 방식)과도 다릅니다.

**근접 인물 제거는 Cloud 허용 노드만으로는 아직 해결책이 없습니다.** 확인한 대안:
- 근접 인물: 기존 `03_지우기_리무브/01_Pika_근접인물+손물체제거`(빈 배경 사진 필요)가 현재 가장 나은 선택입니다.
- VOID(코어, Netflix, 그림자·반사까지 제거): 공식 노트에 '화면을 크게 차지하는 대상은 실패'라고 적혀 있어 근접 인물용이 아닙니다. 원경·중간 크기 대상에는 시험해 볼 만합니다(CogVideoX 기반, 2패스 30스텝·CFG 6이라 무거움).
- H3 Ripple 앵커 전파: 공식 예시가 교체(배경·인물·제품)뿐이고 제거 예시는 없습니다.
- 제작자 방식 그대로(창별 참조 + 이력 연결)는 H3 Relay 커스텀 노드가 필요합니다.
- 원본 파일 노트의 실패 원인 중 'SAM `object_indices`=0(첫 인물만)'과 '손에 든 물체가 person 마스크 밖'은 설정으로 바꿔 볼 수 있습니다(ID 비우기, 물체 이름 추가).

**아직 만들지 않은 새 기능 후보**(노드를 새로 짜야 함): H3 LMS 디테일 2차 패스, live wallpaper, motion transfer, RelayVSR(영상 2배 업스케일), MiniMax-H3-Image, LTX Refine-Details, 긴 영상 Alpha-Gen.
